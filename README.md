# 염주 온라인

고요한 산사를 함께 돌아다니며 염주알과 염주띠를 모으는 실시간 사찰 메타버스 RPG의 첫 버전입니다. 별도의 외부 API 키 없이 실행할 수 있습니다.

인터넷 공개 배포는 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요. Render용 `render.yaml`과 영구 저장 디스크 설정을 포함합니다.

## 실행

Node.js 24 이상이 필요합니다.

```bash
npm ci
npm run dev
```

개발 화면은 `http://localhost:5173`, 실시간 게임 서버는 포트 `3001`에서 실행됩니다. Vite가 `/ws`와 `/api`를 게임 서버로 프록시합니다. 개발 프로세스를 끝내려면 `Ctrl+C`를 누르세요.

배포용 정적 파일과 게임 서버를 한 프로세스로 실행하려면:

```bash
npm run build
npm start
```

기본 포트는 `3001`이며 `PORT`로 변경할 수 있습니다. HTTPS를 제공하는 역방향 프록시에서 WebSocket 업그레이드를 허용해야 합니다. 서로 다른 사용자로 시험하려면 브라우저의 별도 프로필 또는 시크릿 창을 사용하세요. 같은 브라우저 저장소는 같은 방문자 신원을 사용합니다.

## 첫 버전의 게임 규칙

바닥을 클릭하거나 `WASD`·방향키로 이동하고, 마우스 휠로 확대/축소합니다. `E` 또는 **재료 줍기**는 가까운 채집 지점으로 걸어가 재료를 얻습니다. 법당을 선택한 뒤 `Space` 또는 **절 올리기**를 누르면 법당으로 이동해 절합니다. **자동 절**을 켜면 수행을 이어가며, 이동하면 중단됩니다. `I` 또는 **나의 염주**에서 장비를 바꾸고, `Esc`로 메뉴를 닫습니다. 다른 나그네를 클릭하면 염주를 구경할 수 있습니다.

- 테마와 실제 드랍 목록이 다른 10개 채널, 각 채널 최대 108명. 실제 접속 인원만 표시합니다.
- 넓은 사찰과 대웅전·관음전·지장전, 숲·연못·돌탑 주변의 채집 지점.
- 채집 보상과 절 개인 보상, 법당별 공동 108배 보상. 공동 목표 달성 시 해당 회차에 기여하고 접속 중인 수행자에게 염주알과 띠를 지급합니다.
- 목재와 씨앗 소재의 염주알 10종, 삼베·면사·모시·견사 염주띠 6종. 소박·정갈·귀한·진귀·명품의 5등급입니다. 강도와 희소성은 게임 내 균형을 위한 수치입니다.
- 염주알과 띠의 이동 속도·절 속도·드랍 확률·채집 보너스. 띠에 따라 8~36개의 염주알을 장착합니다. 보유 개수와 슬롯 수를 서버가 검증합니다.
- 실제 사용자 간 위치·절 동작·장착 염주 공유와 채널 채팅.

`shared/catalog.js`에서 소재, 능력치, 채널별 드랍 목록과 선호 아이템, 법당과 채집 지점의 좌표를 조절할 수 있습니다. 메시지 형식은 [server/PROTOCOL.md](server/PROTOCOL.md)를 참고하세요.

## 저장과 서버 구조

Node.js HTTP/WebSocket 서버 하나가 10개의 논리 채널을 운영합니다. 독립된 물리 서버 10대를 배포하는 구성은 아닙니다. 위치는 10Hz로 동기화하며 멀리 있는 플레이어는 관심 영역에서 제외합니다. 브라우저는 이름·장비 정보와 반복되는 좌표 프레임을 분리한 압축형 v2 메시지를 사용합니다. 이동 속도, 드랍, 채집 재생성 시간, 절 완료, 공동 수행, 채널 정원은 서버가 판정합니다.

풍경은 반복 오브젝트를 인스턴싱합니다. 가까운 아바타만 상세 모델로 표시하고 나머지 접속자도 묶어서 그리는 간소화 모델로 표시합니다. 상세 아바타의 기본 상한은 데스크톱 20명·모바일 12명, 이름표는 12개·8개입니다. 서버 관심 영역 밖의 사용자는 전송되지 않습니다.

인벤토리·장비·개인 수행 기록은 기본 `data/yumju.sqlite`에 저장됩니다. `DATA_DIR`로 저장 디렉터리를 지정할 수 있습니다. 배포 시 해당 디렉터리에 영구 볼륨을 연결하고 백업하세요. 개발용 데이터 디렉터리는 Git에서 제외됩니다. 채널 내 위치·접속자·공동 수행 진행도는 메모리 상태이며 서버 재시작 시 초기화됩니다.

방문자 토큰은 브라우저 `localStorage`에, 그 해시는 서버에 저장됩니다. 토큰은 계정 비밀번호처럼 취급해야 합니다. 브라우저 저장소를 지우면 방문자 신원을 잃을 수 있습니다. 현재는 회원가입·계정 복구·기기간 동기화가 없는 프로토타입입니다.

실서비스 전에는 계정 인증과 복구, 운영자 도구와 신고/제재, 계정 단위 요청 제한, 부하·지연 측정, 백업 복구 검증을 추가해야 합니다. 여러 프로세스로 확장하려면 채널별 단일 권한 서버로 접속을 라우팅하고, 외부 영속 저장소 및 채널 디렉터리를 공유해야 합니다. 설정된 정원은 동시 접속 성능 보증을 뜻하지 않습니다.

상태 동기화, 요청 제한과 확장 방향은 [server/ARCHITECTURE.md](server/ARCHITECTURE.md)에 정리되어 있습니다.

## 검증

```bash
npm test
npm run build
```

서버 통합 테스트는 이동·근접 판정·채집 쿨다운·장비 소유량, 채널 분리, 중복 신원, 공동 수행 보상, 서버 재시작 후 SQLite 복원, 실제 108개 WebSocket 입장과 109번째 연결 거절을 검증합니다. 이는 정원 경계의 기능 검증이며 전체 1,080명 운영 부하 시험은 아닙니다.

108개 실제 WebSocket 클라이언트를 임시 메모리 DB 서버에서 동시에 이동시키는 전송 검증은 아래 명령으로 재현할 수 있습니다. 측정 조건과 결과는 [server/LOAD_BASELINE.md](server/LOAD_BASELINE.md)에 있습니다.

```bash
PROTOCOL=2 node scripts/load-test.mjs
```

브라우저 기능 검증은 개발 서버를 실행한 상태에서 다른 터미널로 실행합니다.

```bash
npm run test:e2e
```

기본 대상은 `http://127.0.0.1:5173`이며 `BASE_URL`로 바꿀 수 있습니다. Playwright는 `/usr/bin/chromium`이 있으면 이를 사용하고, 그 외에는 설치된 Playwright Chromium을 사용합니다. 필요하다면 `npx playwright install chromium`으로 브라우저를 설치하거나 `CHROMIUM_PATH`를 지정하세요. 실행 결과의 스크린샷은 `test-results/`에 생성됩니다.

브라우저 검증은 두 개의 독립 브라우저 신원으로 실제 접속·상호 표시·채널 이동/분리·염주 장착·키보드 이동·채집·절/공동 수행 기여·채팅·새로고침 후 기록 유지·모바일 배치를 확인합니다. 두 사용자 검증은 정원 전체의 부하 시험을 대신하지 않습니다.

## 이어서 만들 기능

1. 계정 로그인, 캐릭터 꾸미기와 염주 전시·프로필.
2. 채널 테마별 사찰 지형과 계절, 일일 수행·도감 보상.
3. 정원 108명과 전체 1,080명의 실제 부하 시험을 바탕으로 서버 분리·최적화.
4. 아이템 확률·성장 속도 조정, 접근성·모바일 조작 개선.
