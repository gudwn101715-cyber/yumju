# 서버 구성과 운영 경계

현재 구현은 Node.js 24의 한 프로세스에 10개의 독립 월드를 둔 개발용 서버입니다. 각 채널의 동시 연결 상한은 108명이며 게임 판정은 서버가 수행합니다. 클라이언트는 목표 좌표만 보내며, 이동 속도·행동 시간·근접 범위·채집 재생성·보상 추첨·아이템 소유량은 서버가 검증합니다. 단일 이벤트 루프에서 인원 검사와 채널 이동을 연속 실행하므로 마지막 자리에 중복 입장하지 않습니다.

월드는 10Hz로 갱신합니다. 최대 이동 시간 간격을 제한해 서버 정지 후 순간이동을 방지합니다. 다른 플레이어는 85유닛 이내만 전송하고, 공개 염주 표시는 8알로 압축합니다. 개인 인벤토리는 변경 때에만 보냅니다. 256KiB 이상 전송이 밀리는 연결에는 월드 스냅샷을 생략합니다. 메시지는 최대 4KiB, 소켓별 토큰 버킷은 지속 40회/초이며, 채팅은 1.2초에 1회입니다. 참가하지 않은 연결은 15초 후 종료하고, 30초마다 ping/pong으로 끊어진 연결을 정리합니다.

개인 염주·띠·조합·누적 수행 수는 SQLite WAL에 동기 저장합니다. 저장 폴더는 DATA_DIR 또는 실행 디렉터리의 data입니다. 임시 게스트 토큰은 브라우저에 보관하고 DB에는 SHA256 해시만 저장합니다. 이는 계정 복구·다중 기기 인증 시스템이 아닙니다. 브라우저 저장소를 지우면 해당 행자에 다시 접근할 수 없으므로 정식 서비스에서는 계정 연결이 필요합니다. 현재 좌표, 채집 재생성 시각, 공동 수행 진행도, 채팅은 프로세스 메모리이며 재시작 시 초기화됩니다.

배포 시에는 npm run build 후 npm start로 동일 출처의 정적 파일과 /ws를 제공하고, 앞단 프록시에서 TLS와 WebSocket 업그레이드를 활성화합니다. DATA_DIR에는 지속 볼륨을 연결합니다. 프로세스 복제는 아직 지원하지 않습니다. 여러 프로세스를 동일 채널에 연결하면 인원 제한과 월드 판정이 분리되므로 무작정 replicas를 늘리지 않습니다.

정식 운영 단계에서는 채널 소유권을 워커 단위로 고정하고, 게이트웨이에서 채널별 워커로 라우팅하며, Redis로 입장 예약과 존재 상태를 공유하고, PostgreSQL로 사용자·인벤토리 트랜잭션을 옮기는 구성을 권장합니다. 계정 인증·신고와 차단·IP별 접속 제한·관측 지표·백업·부하 시험·복구 시험도 필요합니다. 현재 테스트는 108개 실제 WebSocket 동시 입장 경계를 검증하며, 1,080명 전체의 운영 부하 성능을 보증하는 테스트는 아닙니다.

## 채널별 실제 드랍 목록

개인 채집·절 보상·공동 수행 보상은 모두 해당 채널의 `dropPools` 안에서만 나옵니다. 다른 사찰로 이동하면 얻을 수 있는 소재 자체가 달라집니다. 등급 가중치(소박 52, 정갈 27, 귀한 14, 진귀 5.8, 명품 1.2)에 해당 채널의 대표 아이템이면 3을 곱하고, 선택된 종류의 채널 풀 안에서 합계로 정규화해 추첨합니다. 이 숫자는 절대 드랍 확률(%)이 아닙니다. 개인 절의 보상 발생 확률은 별도로 기본 30%에 염주 능력치를 더하고 최대 80%이며, 발생 뒤 염주알 78%·띠 22%로 종류를 정합니다. 채집은 기본 한 개 보장 후 염주알 77%·띠 23%로 종류를 정하며, 채집 능력치로 염주알 추가 획득을 추첨합니다. 공동 108배는 참여자마다 염주알 한 개와 띠 한 개를 각각 해당 풀에서 추첨합니다.

| ------ | ------------------------------- | -------------------------- |
| 청연사 | 대나무, 편백, 향나무            | 삼베, 모시 합사            |

| 연화사 | 소나무, 연씨, 편백, 천년 보리수 | 삼베, 명주 합사            |

현재 브라우저는 v2 전송을 사용합니다. 첫 입장에서 protocol:2를 선택하면 이름·염주 등 정적 공개 정보는 가시 인원이나 장비 정보가 바뀔 때만 roster로 전송하고, 10Hz frame에는 정수 networkId·좌표·절 종료시각만 담습니다. 노드와 법당은 공유 데이터의 순번으로 압축합니다. 공개 좌표 변환은 채널당 한 번 수행하고 같은 가시 목록의 frame 직렬화 결과를 재사용합니다. protocol을 생략한 기존 도구·테스트는 v1 전체 world 스냅샷을 유지합니다.
